  Property	                Meaning	                                                 		Purpose
A - Atomicity	         All operations in a transaction succeed or none do.	                    Ensures no partial updates.
C - Consistency	         Data must be valid according to rules (constraints, schema).	            Ensures integrity.
I - Isolation	         Concurrent transactions don’t affect each other.	                    Prevents dirty reads, race conditions.
D - Durability	         Once a transaction is committed, it remains even after failure.	    Ensures data is safe permanently.


***1.Atomicity
BEGIN TRANSACTION;
UPDATE employees SET job_title = 'Senior Developer' WHERE emp_id = 101;
UPDATE employees SET salary = 70000 WHERE emp_id = 101;
COMMIT;
What if something fails?
Let’s say the salary update line fails due to a bug or power outage. Thanks to Atomicity, the entire transaction is rolled back, and Rahul remains a Developer with ₹50,000 salary.
✅ Guarantees no half-done updates.

BEGIN TRANSACTION;
UPDATE accounts SET balance = balance - 100 WHERE name = 'Alice'; -- Debit
UPDATE accounts SET balance = balance + 100 WHERE name = 'Bob';   -- Credit
COMMIT;


How ACID works here:
Atomicity: If Bob’s account update fails, Alice’s debit is rolled back.

Consistency: The total money (Alice + Bob) before and after stays the same.

Isolation: If someone checks Bob’s balance during this process, they don’t see partial changes.

Durability: Even if power goes off after COMMIT, Bob will have ₹100 added.

);

-- Now create the 'employees' table using all constraints
CREATE TABLE employees (
    emp_id INT PRIMARY KEY,                             -- PRIMARY KEY
    emp_name VARCHAR(100) NOT NULL,                     -- NOT NULL
    email VARCHAR(100) UNIQUE,                          -- UNIQUE
    salary DECIMAL(10, 2) CHECK (salary > 0),           -- CHECK
    hire_date DATE DEFAULT CURRENT_DATE,                -- DEFAULT
    dept_id INT,                                        -- FOREIGN KEY reference
    FOREIGN KEY (dept_id) REFERENCES departments(dept_id)
