### Implement SCD type 2 in the SPARK :
            from pyspark.sql import SparkSession
            from pyspark.sql.functions import (col, lit, current_date, expr)

           
            
            # 1. Spark Session
             # -------------------------------------------------------
            spark = SparkSession.builder.appName("SCD_Type_2_Customer").getOrCreate()
            
            # 2. Read Source (daily incoming data)
            # -------------------------------------------------------
            src_df = spark.read.parquet("/source/customer") 
            # Expected columns:
            # customer_id, name, city, phone
            # 3. Read Target Dimension Table
            tgt_df = spark.read.parquet("/dim/customer")
            # Expected columns:
            # customer_id, name, city, phone, start_date, end_date, is_current
            # 4. Filter current records from target
            # -------------------------------------------------------
            tgt_current_df = tgt_df.filter(col("is_current") == "Y")
            # -------------------------------------------------------
            
            # 5. Join source with current target
            # -------------------------------------------------------
            
            join_df = src_df.alias("src").join(tgt_current_df.alias("tgt"), on="customer_id", how="left")
            
            # ------------------------------------------------------
            # 6. Change detection logic
            # -------------------------------------------------------
            change_condition = ((col("src.name") != col("tgt.name")) |(col("src.city") != col("tgt.city")) |(col("src.phone") != col("tgt.phone")))
            
            # -------------------------------------------------------
            
            # 7. Expire old records (changed records)
            
            # -------------------------------------------------------
            
            expired_df = join_df.filter(change_condition & col("tgt.customer_id").isNotNull()).select( col("tgt.customer_id"),col("tgt.name"),col("tgt.city"),col("tgt.phone"),col("tgt.start_date")
).withColumn("end_date", current_date() - expr("INTERVAL 1 DAY")).withColumn("is_current", lit("N"))
            # 8. New records (new customers + changed customers)
            new_df = join_df.filter(change_condition | col("tgt.customer_id").isNull()).select(col("src.customer_id"),col("src.name"),col("src.city"),col("src.phone")).withColumn("start_date", current_date() ).withColumn("end_date", lit("9999-12-31")).withColumn("is_current", lit("Y"))
            # 9. Unchanged records
            
            # -------------------------------------------------------
             unchanged_df = tgt_current_df.join(
            
                expired_df.select("customer_id"),
            
                on="customer_id",
            
                how="left_anti"
            
            )
            final_dim_df = unchanged_df.unionByName(expired_df).unionByName(new_df)

 ####Describe how you handle schema evolution in a production pipeline. What happens if a producer adds a new column unexpectedly?
 Anwer:
            In  production, I separate schema flexibility and schema enforcement using a Medallion architecture.
            In the Bronze layer, I allow schema evolution using mergeSchema or Auto Loader’s addNewColumns mode so ingestion never fails. 
            In the Silver layer, I enforce a strict schema and validate data types.
            If a new column is added, I log and review it before propagating downstream. 
            If a datatype changes unexpectedly, I treat it as a schema violation and either quarantine those records or alert upstream producers. This ensures robustness and prevents silent data corruption.
